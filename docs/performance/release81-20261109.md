# Version 1.0 / Build 81 — E2EE reliability

## Scope

Reconstructed from the hash-verified published Build 80 source snapshot. The GitHub history previously held an older native app; this commit synchronizes that already-published baseline before adding the changes below. Unpublished AI attachment work and unrelated working-tree changes are excluded.

- Retain the bootstrap/pre-key header until an authenticated peer response establishes the receive chain, so dropping the first outgoing envelope does not make the next envelope unreadable.
- Read-only historical ciphertext retry never overwrites the live ratchet or consumes one-time prekeys.
- Refetch MLS recovery status when an in-flight Welcome advances the epoch; restore missing local MLS state before decrypting.
- Tapping an unreadable bubble retries that message; group retry uses MLS loading rather than private-session reset.
- Preserve published message sort/row cache invalidation, account-scoped synchronization throttling, structured cancellation and deadline handling.

No backend deployment, database/schema migration, key reset, APNs route change, new dependency version, or export-compliance change is included.

## Validation

All seven scoped suites passed against this release snapshot: 56 private encryption assertions, selected-message retry, MLS epoch/recovery, MLS store preservation, 22 MLS security assertions, group-send/draft flow, and 23 published chat cache/concurrency assertions. Synthetic fixtures do not read device keys or production message content.

Release archive/signature/upload status is recorded in the release artifacts and will be updated after Apple responds. Upload target is TestFlight only; no formal App Store review submission.

## TestFlight test plan

1. Two test accounts: private messages in both directions; receive while the first sender message is delayed; tap an unreadable historical bubble and confirm the current conversation remains usable.
2. Group messages: existing state, cold restart and a fresh Welcome/epoch update. Confirm failed retry retains an explicit error and does not silently recreate keys.
3. Change accounts and return to chats; verify cached messages/rows do not leak across accounts.
4. Recheck stickers, voice/video calls and foreground/background notifications on real devices.

A missing historical private key cannot be reconstructed by retry. Live iOS-to-iOS exchange, multi-device delivery, APNs and physical-device acceptance remain pending.
